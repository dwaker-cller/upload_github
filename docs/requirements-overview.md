# 需求与验收概要（脱敏版）

## 产品角色

- **广告主**：创建任务、查看报名、确认合作、终审内容并维护企业资料。
- **达人**：浏览机会、报名或接受邀请、跟踪合作、提交内容并查看收益。
- **运营**：审核任务、报名和内容，管理用户，并维护官方任务。

## V1.0 核心闭环

```text
广告主发单
  → 运营审核
  → 达人报名/接受邀请
  → 运营初审
  → 广告主确认合作
  → 达人提交内容
  → 运营初审
  → 广告主终审
  → 发布确认/合作完成
```

## 关键业务原则

- 广告主任务经运营审核通过后，才对达人开放。
- 达人报名或接受邀请后，先进入运营审核，再由广告主确认。
- 内容被驳回并修改后，必须重新经过运营初审。
- 报名、审核、内容提交等关键动作需要防止重复执行。
- 驳回必须填写原因，并对相关角色可见。
- 列表、详情、日志和通知中的状态需要保持一致。
- 合作名额检查应在服务端原子化执行。
- 三类角色的数据与操作权限需要严格隔离。

## 交互验收关注点

- 表单同时具备字段级提示和提交时强校验。
- 列表提供搜索、筛选、重置、刷新、加载、空态和错误反馈。
- 提交中的操作按钮需要 loading/disabled，避免重复提交。
- 提交型动作使用明确的确认与结果反馈；只读详情优先使用抽屉。
- 驳回、停用等高影响动作需要原因与二次确认。
- 原型中的提示不能替代真实的后端状态流转、日志和持久化。

## Demo 范围边界

- 新手引导 Demo 聚焦达人端练习流程，不包含广告主端实操。
- 社媒认证 Demo 用于交互验证，不执行真实 OAuth，不读取平台数据。
- 两个 Demo 均没有后端、权限系统、持久化数据库或真实通知服务。
- 正式验收仍需在授权测试环境验证接口、状态机、日志和数据隔离。
