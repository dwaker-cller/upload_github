# 测试与问题跟进方法

## 测试框架

### 主流程

1. 广告主创建并提交任务。
2. 运营审核任务。
3. 达人浏览、报名或接受邀请。
4. 运营审核报名，广告主确认合作。
5. 达人提交内容。
6. 运营初审，广告主终审。
7. 发布确认并记录合作完成/结算状态。

### 异常流程

- 任务驳回后修改并重新提交。
- 重复报名、重复审核和重复提交的拦截。
- 报名报价越界、必填缺失与格式错误。
- 内容驳回后重新进入运营初审。
- 合作名额满后的原子化拦截与剩余申请处理。
- 权限不足、接口失败、超时、空数据和加载状态。

## 单条问题的最小记录

| 字段 | 说明 |
| --- | --- |
| 标题 | 页面/模块 + 动作 + 异常结果 |
| 前置条件 | 角色、数据状态和必要配置 |
| 复现步骤 | 可重复执行的最短操作路径 |
| 当前结果 | 实际页面、接口或状态表现 |
| 期望结果 | 依据需求/验收标准的正确行为 |
| 严重程度 | 对主流程、数据一致性或体验的影响 |
| 证据 | 脱敏截图、时间点和必要日志 |
| 跟进状态 | 待确认、修复中、待回归或已关闭 |

## 回归检查

- 列表与详情的数据、状态和操作入口一致。
- 修改后回显正确，刷新页面后状态仍保持。
- 驳回原因对正确角色可见，历史记录可追溯。
- 请求进行中按钮禁用，连续点击不会产生重复数据。
- 不同角色只能访问授权范围内的数据和动作。
- 修复目标问题的同时检查相邻流程是否受影响。
